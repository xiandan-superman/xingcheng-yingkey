# Windows 授权服务维护

桌面程序为 v0.10.4，当前服务为 v0.10.2。产品设计方包提供无业务数据的服务材料与 Node 运行时；仓库不存放运行时 exe、生产数据或管理凭据。

## 布局

服务根目录放置 `node.exe`、`install.ps1`、`supervisor.ps1` 和 `service-settings.json`；`server/` 使用仓库对应目录，`src/core/` 包含 `online.mjs`、`policy.mjs`、`groups.mjs`。

复制 `service-settings.example.json` 后按实际域名及受控代理配置。默认监听 `127.0.0.1:17891`。首次启动创建本机授权状态及初始维护登录信息，保存在 `server/data/`，必须用操作系统权限限制读取。

## 统一账号

1. 在独立账号中心登记映钥客户端、准确的 HTTPS 回调 `https://你的服务域名/sso/callback` 和 `openid profile` 范围，启用 S256 PKCE。
2. 将 `identity.example.json` 复制为服务的 `server/data/identity.json`，在服务器上填写实际接入凭据并启用，不能提交或分发该文件。
3. 为员工分配平台访问。平台管理员映射为管理员；普通成员具备 `operate` 权限时可操作，否则只读。账号中心管理员不自动获得业务权限。
4. 确认账号中心授权页安全策略允许登记的回跳域名，并继续由协议服务校验完整回调地址。不要用任意域名或通配回调代替校验。

该账号服务不开放密码授权；桌面通过系统浏览器登录，再取得独立员工会话。映钥实时检查平台授权。接入凭据只存在于服务器，不能放入桌面程序。

默认桌面程序绑定量子星橙公司服务；其他部署需要维护人员调整受信地址并重新构建，不能只修改旧连接文件。

## 升级与保留

已有服务器不能重新初始化。先备份程序和完整数据，用数据副本检查兼容性，再替换程序，验证密钥、账号映射、原许可签名及计数。回退程序不覆盖当前业务状态，否则可能回退次数。

删除记录时保留回收站标记与原授权计数。旧许可重新上传不能绕过删除或清零；恢复授权仍为停用，需要管理员明确启用。

可信代理默认关闭，仅在源站绑定回环且入口受控时启用。网页保留 `no-transform`，避免代理注入脚本破坏安全策略。生产使用 HTTPS；安装脚本和示例不提供公共管理员凭据。
